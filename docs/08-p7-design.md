## 2. 从冻结结果得到的证据

运行 `uv run python scripts/analyze_p6.py` 可重现本节。脚本校验 Pilot、P6 预测哈希，并逐项重现五份已有 report；仅读取本地冻结产物。详细输出为 `runs/p6-analysis-v1/summary.json`，不入 Git。日期容差、IoU、并集回放及全阳性检查都是事后诊断，不替换正式评价。

### 2.1 Point：定位误差和过度报警同时存在

| 方法/诊断 | TP | FP | FN | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| P5 SR，精确日 | 317 | 389 | 126 | 0.4490 | 0.7156 | 0.5518 |
| P6 Visual，精确日 | 47 | 1338 | 396 | 0.0339 | 0.1061 | 0.0514 |
| Visual，±1 日诊断 | 136 | 1249 | 307 | 0.0982 | 0.3070 | 0.1488 |
| Visual，±3 日诊断 | 276 | 1109 | 167 | 0.1993 | 0.6230 | 0.3020 |
| Visual，±7 日诊断 | 372 | 1013 | 71 | 0.2686 | 0.8397 | 0.4070 |
| SR ∪ Visual，精确日回放 | 327 | 1711 | 116 | 0.1605 | 0.7381 | 0.2636 |

容差诊断在每例每轴内对去重后的日期做最大数量一对一匹配，两路均采用同一容差；不是恢复旧版 P4 的按类型容差。Visual 在 ±3 日内能接近许多目标，但 Precision 仍只有 0.1993。其完全没有任何 GT 事件的成功轴也有 252/423 报警，不能只归因于坐标读数偏移。

直接并集只比 SR 多 **10 TP、1322 FP**，不支持不加复核地拼接两路。该回放把失败视觉视为无可用候选、保留成功数值结果；其组合成功率 1.0 不表示视觉调用全部成功，也不代表零端到端成本。

12 个 Point 失败案例实际只包含 4 个 Point GT 日。即使把这 12 例全部变成完美预测，并保持其余输出不变，F1 上限也仅为 **0.0557**。这是解释格式失败影响的 oracle 诊断，不是新方法成绩；修复 JSON 不能独自解决 Point 检测问题。

### 2.2 Range：活动区间语义与边界都要检查

| 方法/诊断 | Affiliation F1 | 任务负轴 FAR | 正轴平均逐日 IoU |
| --- | ---: | ---: | ---: |
| P5 Rolling Theil–Sen | 0.9345 | 0.1954 | 0.3398 |
| P6 Visual | 0.7573 | 0.5506 | 0.3719 |
| Theil–Sen ∪ Visual 回放 | 0.9052 | 0.5307 | 0.4055 |
| 所有轴均预测 [0,364]，指标自检 | 0.6835 | 1.0000 | 0.1692 |

IoU 将同轴 GT 活动区间与预测分别合并为日期集合，在固定 **199 个 GT 正轴**上平均；失败/空预测记 0。它不含负轴，必须同 FAR 一起看。并集回放沿用上述数值回退，因此 FAR 的成功负轴分母是 701，Visual 自身是 632；不能用二者 FAR 的细小差别声称视觉被改善。

全阳性检查说明：在本数据与当前聚合口径下，较高 Affiliation 分数本身不能证明精确定位或低误报。这不是评价器实现错误；Affiliation 是基于时间距离的指标，并不等于区间重叠率。[Huet 等，KDD 2022，Local Evaluation](https://ahstat.github.io/images/2022-anomaly1-kdd-paper.pdf)

更具体的语义证据：24 个 Single Step 中，Visual Range 成功 23 例，**23 例都在 Step 轴报了区间，21 例一直报到第 364 日**。而 P4 中 Step 仅属于 Point 起点任务。原 Range prompt 只要求“continuous anomalous time ranges”，没有明确活动过程与永久偏移的区别，因此这里存在任务契约未充分传达的合理解释，不能都解释为视觉能力不足。

视觉也有值得保留的局部优势：24 个 Single Transient 的平均逐日 IoU，Visual 为 **0.6562**，Theil–Sen 为 **0.2189**；相应 Affiliation F1 却为 0.9516 与 0.9702。这提示视觉可能提供更合适的候选边界，仍不能据此按真实类型路由。

### 2.3 数值方法也存在能力缺口

24 个 Single Spike，SR 精确命中 24 个；24 个 Single Step，SR 只命中 2 个，而已冻结的 PELT 命中 19 个。这说明按全局 Point F1 选出的单方法不保证覆盖每一种形态。

P7 第一轮仍使用已选中的 SR/Theil–Sen，保持比较可归因。暂不改变 P5 的选择、不新增数值 ensemble。若候选缺失成为限制，后续应另立数值候选覆盖实验，并给它独立的 numerical-only 对照；不能按 GT 类型选择 SR 或 PELT。

## 3. 论文调研如何影响设计

下列来源均为论文正文或官方文档；不同论文的任务、阈值选择和指标不同，不与本项目数值横向排名。

| 来源 | 已核实的方法/发现 | 本项目采用或暂缓的内容 |
| --- | --- | --- |
| [Can Multimodal LLMs Perform Time Series Anomaly Detection?，VisualTimeAnomaly v2，WWW’26](https://arxiv.org/html/2502.17812v2) | 正文包含 TSAD-Agents 的 scanning、planning、detection、checking；按点/区间粒度使用不同模态及传统检测工具，并对候选复核 | 借鉴粒度分工和复核；不直接搬入类型扫描、动态路由或多 Agent。我们已有固定 Point/Range 两任务 |
| [Harnessing Vision-Language Models for Time Series Anomaly Detection，VLM4TS](https://arxiv.org/html/2506.06836v2) | 先用 ViT4TS 的视觉编码器定位候选，再给 VLM 全局图和候选端点做验证/修正 | 借鉴明确候选位置与全局上下文。用现有数值和纯视觉输出作候选，是适配设计，不是该论文的官方复现；论文第一阶段并非 SR/Theil–Sen |
| [Can LLMs Understand Time Series Anomalies?，AnomLLM](https://arxiv.org/html/2410.05440v3) | 在其受测模型与任务中，图像有优势；显式 CoT 未改善，反而降低检测表现 | 保持直接结构化回答，不把更长推理或开启 thinking 当作默认优化；不把论文结论推广为所有模型都不应推理 |
| [See it, Think it, Sorted，TAMA](https://arxiv.org/html/2411.02465) | 研究 few-shot 多模态异常分析与参考示例 | 暂不加 few-shot；它改变零样本设定，也引入示例选择成本，不是当前最小改动 |
| [AnomSeer](https://arxiv.org/html/2602.08868v2) | 通过专家轨迹和 RL 后训练改进时序检测，训练轨迹构建使用 GT | 暂不训练或微调，不把“多写统计说明”称作复现，也不能把训练阶段 GT 用法搬到我们的推理阶段 |
| [JSONSchemaBench](https://arxiv.org/abs/2501.10868) | 系统评估受约束结构化生成的能力与限制 | 输出结构与检测质量分别验收；合法 JSON 不等于符合 N/E/U 契约，更不等于检测正确 |

工程上，阿里云文档明确区分 `json_object` 与 `json_schema`，在支持列表中列出 Qwen3.8-Flash。旧 P6 用的是前者。文档的简表仍有“Only selected qwen-plus”旧描述，与详细支持列表不一致，因此必须在本机实际端点做带图预检，不能仅凭文档认定 schema 已生效。[官方结构化输出文档](https://help.aliyun.com/en/model-studio/qwen-structured-output)

## 4. P7a：最小纯视觉改进对照（待实施）

### 4.1 两个条件，区分结构与语义

| 条件 | 图像与模型 | 唯一改动 | 目的 |
| --- | --- | --- | --- |
| A / `visual-schema-v2` | 复用 P6 原 PNG、模型与采样参数 | 原提示 + 严格 JSON Schema | 验证结构可靠性 |
| B / `visual-task-v2` | 与 A 相同 | 在 A 上明确任务边界 | 检查跨任务误报、残留尾部与空正常输出 |

原 P6 作为历史参照；A/B 在同一运行期按固定顺序交错执行，以减小服务时间漂移。不能把 A 对历史 P6 的差异全部因果归于 schema，服务与采样也可能变化。B−A 才是本轮较直接的语义对照。

Schema 要求根对象只有 N/E/U，字段均 required、`additionalProperties=false`；Point 为整数日期数组，Range 为长度 2 的整数数组的数组。程序继续严格核对 0～364、`start<=end`、重复键和响应型号。schema 支持的约束由实际端点预检确认；端点不支持时停止该条件并记录，不静默退回旧模式。

### 4.2 提示只补齐任务定义

两任务共同说明：缓慢平滑的周期变化和普通随机波动本身不构成目标；允许所有轴为空，不要求每例都有异常。逐轴独立判断，其他轴没有同步变化不能作为排除异常的理由。

- Point：孤立异常日，或进入一个持续新水平的突变首日。持续演化过程不是一串 Point；暂时异常区间的两侧边界不另列 Point。
- Range：持续演化的活动过程，或暂时偏离后回到此前水平的完整异常区间。稳定的新水平仅是一次突变的残留偏移时，不报整段 Range；持续演化结束后保留的稳定偏移也不延伸标注。
- 同一轴可以出现两种任务的目标，不假定互斥、不要求输出类型或成因。索引从 0 开始，区间闭合。

这是公开检测目标定义，所有方法都应明确知道；提示不包含注入幅值、14/90 日时长、安全区 60～304、每例事件数、scenario、case_id 或真值。仅凭图像不能确定的边界仍可出错，不能事后强制对齐 GT。

同时承认任务的建模限制：真实观测中的“两次相反突变”和“一段临时偏移”可能外观相同。当前 Point/Range 划分依赖合成事件的定义，并不是所有现场曲线都可唯一判定的自然分类。新版提示只能明确本实验目标，不能消除这种不可辨识性，也不能据此声称识别了成因。

第一轮不同时改变画法、拆轴、增加多尺度窗或原始数值表，以避免无法归因。若 B 仍有定位偏移，由 P7b 测试候选坐标约束；只有其证据不足时才另开单轴/局部图实验。

### 4.3 开发子集与预算

从已用于分析的 Pilot 中确定性选 **60 例**：Normal 6；Single 每 type×axis×sign 一例共 30；六 Multi scenario 各 4 共 24。在各层按 case_id 取前若干个并保存 manifest。仅用预定义元数据分层，不按本次错误表现或曲线选择。整个 Pilot 都已被分析，剩下 240 例不能再称未见测试。

先用 Pilot 外的 12 张人工图（正常、瞬时点、突变、暂时区间、持续变化及混合）各测 Point/Range，共 24 次工程调用。结构预检要求全部通过；不根据检测 F1 调参。随后 A/B 各 60×2 次，合计 **240 次**正式开发调用；每逻辑请求一次，无修复重试。失败保留对应案例。

A 是归因对照；B 是事前指定的新任务语义条件，不根据子集 F1 在 A/B 间挑赢家。记录精确 Point、原 Affiliation、原 FAR、执行成功率，另附固定正轴 IoU、±1/3/7 日诊断与错误类别计数。

## 5. P7b：固定候选复核（历史设计，执行见第 12 章）

核心问题是：**给出两路候选和全局图，模型能否删掉错误候选、保留有效候选，而无需重新估读日期？**

```text
input ── P5 SR / Theil–Sen ── numerical candidates ─┐
                                                   ├─ 合并候选表 ── 一次视觉复核 ── P4
input ── P7a B 纯视觉 ─────── visual candidates ────┘                 ↑
input ── 原始 N/E/U 全局图 ────────────────────────────────────────────┘
```

1. 每任务按 N/E/U、start、end 排序，完全相同的位置去重；保留来源记录。Point 候选为单日；Range 保留两路各自的完整区间，不提前把重叠区间拼成一个长区间。
2. 为候选赋确定性 ID。给复核器原图、候选 ID/轴/精确索引和与 B 一致的任务定义；来源留在日志，不提供 GT、模拟类型或“正确候选”等暗示。
3. 输出仅为 `{"keep_ids":[...]}`。只能保留或删除已有候选，不新增、挪日、伸缩边界或输出解释。未知 ID、重复 ID、缺字段视为结构失败。不加 confidence 阈值。
4. 两路任一来源都可以独立贡献最终候选，不要求两路共同支持。空候选不调用复核器，输出成功空集合。
5. 每 case×task 最多一次复核；Point/Range 独立。输入候选长度、512 输出 token 上限在 Pilot 外预检；遇到截断不能悄悄删候选，按失败保留。正式阶段不临时改预算。
6. B 失败或复核失败时，C 的主结果为失败空预测，按 P4 计分；同时记录具体失败阶段，不把回退数值包装成模型成功。用于工程可用性的回退策略须另列，不能混入 C 主成绩。

此处借鉴 VLM4TS 的“候选 + 全局上下文”机制，但我们有独立视觉分支，且第一轮限制为 ID 选择，以单独检验候选筛选能力。它是固定两阶段流程，不是 Agent，也不是论文完整复现。

同一子集比较四项：N（原 P5 选择）、V（B）、U（无复核的候选并集，仅离线）、C（候选复核）。复用 B 的同期结果，不再为 C 重跑视觉；最多增加 **120 次**复核，连同 P7a 共最多 **360 次**开发请求（另有 24 次预检）。记录端到端数值耗时、渲染、两阶段 token/请求/失败，不能把复用等同于零成本。

U 的回退语义与第 2 节一致，需同时报告其 V 阶段成功率；C−U 的算法差异另在共同成功案例上做成对诊断，主表仍保留全部案例，避免因失败分母不同而夸大复核收益。

### 候选限制必须明确

- Point 的精确召回上限是候选集中已有的正确日期。复核不能补出两路都没报的 Step，也不能把偏移三天的候选自动移动到正确日。
- Range 可在两个不同边界候选之间选择，但不能恢复候选集合中不存在的边界。不能声称该版本实现了自由边界精修。
- P5 的总体选择及同一 Normal 校准偏差仍存在。上述限制如果主导结果，应先决定是否研究候选生成，不能堆叠复核轮数或新增 Agent 来掩盖。

## 6. 确认数据与继续/停止条件

开发 60 例只用于可行性分析。完成代码和协议后，先冻结 B/C，再按 `event-v6` 原参数另建 **300 例独立确认集**：保持原 30/120/150 配额与分层规则；使用新 namespace，核对所有 case seed、背景成分 seed、input 哈希均不与 Pilot 重复。重复时仅依这些身份元数据确定性重采样，禁止按曲线质量筛选。新数据 ID 和 manifest 独立，不能覆盖 `pilot-v1`。

确认集按冻结 P5 参数重新计算 N，B 最多 600 次调用、C 最多 600 次追加复核，U 离线生成。不重新校准阈值、不更改提示或按确认分数重新选方案。它只检验同一受控模拟分布的推广；若用该集继续调参或设计 Agent，它就成为验证集，之后仍需独立最终测试。

P7 工程验收：数据与源码版本可追溯、真值访问隔离、输出覆盖完整、失败不删例、无隐式重试、请求与成本可核对。设计中不设通用“F1 合格线”。

继续考虑 Agent 的证据应是：在确认集上，固定复核相对 N/U 显示可重复解释的收益，并明确其 FAR、Recall、IoU 与成本代价。如果仅降低 FAR 却明显丢召回，报告权衡；如果没有净收益，保留 N/V 独立基线并停止增加复杂度。不能要求必须得到组合优于单方法的结果。
