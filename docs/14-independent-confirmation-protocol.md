# 独立合成确认协议：冻结数值与纯视觉比较

> 2026-09-28 · 设计草案，尚未冻结为可执行实验。未生成确认数据，未调用模型，未实现 bootstrap。正式运行前需通过第 8 节 Gate；当前不批准绕过 P7b 的停止条件继续组合实验。

## 1. 目标、主比较与范围

**执行顺序更新（2026-09-28）：** 用户已授权先进行 [P8a 视觉 Range 开发优化](15-p8a-visual-range-context.md)，再依据证据决定后续协作方法。本文继续作为未执行草案；确认集维持未生成/未使用。最终比较方法必须在独立确认开始前重新登记，下面 N/V 选择不自动继承为最终方案。

检验开发阶段已确定方法在新随机实现、同一受控合成分布上的表现是否稳定。主比较为 Point 的 SR 与 Visual semantic-v2-8k，以及 Range 的 Rolling Theil–Sen 与 Visual semantic-v2-8k。新视觉版本按用户 2026-09-28 指令将最大回复 tokens 从 512 提升至 8192，提示保持 semantic-v2；这属于调用预算变更，不能称与旧 v2 全部参数相同。四个条件分别独立推理，视觉不知道数值候选，数值不知道图像判断。

| 任务 | 数值条件 N | 视觉条件 V | 主指标差值 |
| --- | --- | --- | --- |
| Point | 冻结 Spectral Residual | visual-semantics-v2-8k Point | Δ = F1(V) − F1(N)，精确日 |
| Range | 冻结 Rolling Theil–Sen | visual-semantics-v2-8k Range | Δ = Affiliation F1(V) − Affiliation F1(N) |

不设“必须视觉更好”的假设。两项差值分别解释，允许正负不同。P5 的 PELT/Matrix Profile、Visual v1、U/C 继续保留全部开发材料，不新增其确认调用；没有 P7b 候选复核，也没有 Agent。若需要增加方法，必须在生成确认集与查看成绩前另行修订，不事后补选开发表现有利的分组方法。

方法拆分参考 [VisualTimeAnomaly（WWW 2026 v2）](https://arxiv.org/html/2502.17812v2)的多粒度能力比较；这里是 GNSS 任务的同分布确认，不声称上游基准复现。Point 精确/容差及 Range 关联/重叠的含义见[方法手册](11-experimental-handbook.md)。

## 2. 数据设计与独立性检查

拟命名 `confirmation-v1`，总计 300 例，仍为 event-v6、2025 年 365 日、毫米、原三轴背景/噪声/事件公式及六场景。配额与 Pilot 一致：30 Normal、120 Single（五形态 × 三轴 × 两符号 × 每格 4 例）、150 Multi（六场景 × 25）。不扩展幅值、噪声、时长或场景，不人为拉平 Multi 事件数。

建议在新包装器中固定根 seed=20260928、独立种子命名空间 `confirmation-v1`；命名空间到整数常量及其派生算法必须在实现时显式登记并冻结后才生成。保留原 Single type/axis/sign 确定性元数据分层规则。模型输入仍使用不含类型信息的 case_id，数据身份由包 ID + case_id + 哈希共同确定，不能仅用旧 `case_0001` 等字符串关联缓存。

生成后仅做预定完整性检查：配额、形态元数据、有限值、连续日历、input/truth 一致性、跨开发集 case seed 与背景/噪声种子重复检查、序列内容哈希重叠检查。内容去重哈希应排除 case_id 等身份字段，分别检查位移序列与背景/噪声数值；不能把改名视为独立。共享季节公式和事件模板是受控分布设计，不是随机背景独立性的证据。

如发现种子/序列重复或结构错误，停止并记录，不自动挑选替代曲线；在任何检测结果可见前修复生成包装器、重新登记版本。不得按曲线是否显著、噪声大小、模型可见性、事件检测率或好看程度拒收。所有生成质量检查由准备阶段进行，检测进程只收到无标签包。

## 3. 版本与输入冻结

冻结 `configs/p5-frozen.json` 的现有阈值，禁止用确认 Normal 再校准；它们是评价样本，不是新的训练集。冻结 semantic-v2 的完整提示、严格解析规则、renderer-v1 图像、qwen3.8-flash、thinking=false、temperature=0、max_tokens=8192、JSON Object、4 workers、120 秒、每 case×task 一次尝试。新配置为 `configs/p8-visual-8k.json`，方法标识 `visual-semantics-v2-8k`；旧 P6/P7a 的 512 和 P7b 的 2048 保留在历史记录中。增加上限不表示每次必定消耗 8192 tokens，也不能直接沿用旧 v2 成绩作为新配置实测结果。

已新增 `visual_8k.py` 请求适配器，其实际 payload 已由 MockTransport 测试验证为 8192；新确认运行器仍待实现，届时必须使用该适配器和新配置。旧 `visual`、`visual-semantics`、P7b CLI 仍服务各自历史协议，不会因新配置而静默改变。实际服务对 8192 的接受情况尚未经新模型调用预检；若拒绝，应报告失败而非自动降回旧预算。实施可新增 dataset-neutral 包装器，但 numerical.py、visual.py、旧参数/提示文件不改。在 Pilot 外工程样例上验证新入口与原检测函数等价；模型调用无确定性保证，只验证请求内容、解析和记录一致性，不要求工程样例新旧输出相同。

清单至少包含生成/分层算法、全部方法与评分源码规范化哈希、uv.lock 与依赖版本、参数/提示/图像哈希、renderer 字体/绘图环境、输入包及评分真值清单哈希。准备完成后封存输入包和评测包，推理只读取输入包；指标和原始 truth 只在全部推理结果封存后打开。代码读路径隔离不等于 OS 沙箱，报告中如实说明。

## 4. 执行和失败规则

先在 Pilot 外执行固定的 6 个人工序列 × 两任务，共 12 次工程预检，验证传输和结构；预检无准确率门槛。任一预检失败则保留记录并暂停正式运行，修复传输必须另记版本，不能反复抽到成功而隐去失败。正常完整路径最多 600 次正式视觉调用，加 12 次预检；数值不产生模型请求。

正式任务顺序按 case_id 排序、每例 Point 后 Range 排队，最多 4 worker；按索引持久化结果，完成顺序不改变评价。记录请求/完成 UTC 时间、实际模型 ID、响应 ID、finish_reason、usage、延迟、失败原因与图像/提示哈希。模型服务别名可能漂移，不将 qwen3.8-flash 字符串视为权重永久固定的证明。

每次发送前以排他创建方式写 attempt_started；在中断、超时或响应丢失后不自动再次发送。恢复只处理从未发送的项，对已发送但无法确定结果的项记失败。完成后每个任务、方法必须有全部 300 行：数值计算异常或模型结构/API 失败均为 failed，不能删除或当正常空预测。畸形输入或登记哈希不符属于实验完整性错误，应在调用前终止，而不是混成方法失败。

保留原 semantic-v2 解析行为，包括现有完整 JSON 围栏接受规则；不因确认结果更换解析器。新规则若有必要，应另立版本。没有结构纠错、人工修补、按分数重跑或最佳重复挑选。

### 4.1 JSON 格式核查（2026-09-28）

历史 P6/P7a/P7b 请求均显式指定 `response_format: {"type":"json_object"}`，提示也要求 JSON；未发送服务端 `json_schema`。客户端随后验证必需字段、轴、整数日期范围或候选 ID 白名单。合法 JSON、合法 JSON 对象、满足任务 schema 是三个不同要求。

| 历史运行 | 标准 JSON 对象 | 合法 JSON 数组（任务结构失败） | 未获得响应 |
| --- | ---: | ---: | ---: |
| P6 Point（300） | 288 | 12 | 0 |
| P6 Range（300） | 273 | 27 | 0 |
| P7a Point（300） | 297 | 2 | 1 |
| P7a Range（300） | 281 | 19 | 0 |
| P7b 正式复核（107） | 107 | 0 | 0 |

本表核验模型原始 content，严格解析时拒绝重复 JSON 键及非标准数值常量，不把落盘日志的 JSON 外壳当作模型结构正确的证据。所有有响应记录的 finish_reason 均为 stop；P7b 单次 completion_tokens 最大为 62，未发现 token 截断记录。数组也是合法 JSON，但不是约定的顶层对象，因此仍记失败。8192 的新上限不能据此解释或自动解决历史结构失败，本轮未重跑历史实验。

## 5. 评价与指标解释

全部 300 例为每方法固定评价集合。Point 主指标是精确日微 P/R/F1；±3 日一对一最大基数匹配为预定补充。Range 主指标是正 case×axis 上 Affiliation P/R/F1 宏平均；正轴逐日 IoU 与全轴日微 F1 为补充。使用现有 comparison-views-v1，不改变宏/微权重，不以 F1(平均 P, 平均 R)替代平均轴 F1。

每方法报告任务负轴 FAR、有效负轴数、失败负轴数、执行成功率，以及 Normal-only 的成功轴 FAR、报警日数量与失败率；失败进入正样本召回分母，失败 Normal 不算 clean。Normal 无阳性 F1 为 N/A。FAR 与成功率必须一起阅读，不允许通过方法失败缩小分母获得“低误报”结论。

整体主表优先，按 Single 形态、轴、六 Multi 场景的结果为预先指定的描述性分组。多事件分组真值只用于事后评分，不进入提示、工具或方法选择。同一案例可包含多类事件；类型诊断必须说明是否重叠计数，不能把类型覆盖相加当作总 TP。

选用多种度量参考 [Affiliation 原文](https://arxiv.org/abs/2206.13167)与[指标综述](https://link.springer.com/article/10.1007/s10618-023-00988-8)。[严格 TSAD 评价研究](https://arxiv.org/abs/2109.05257)提醒 point adjustment 可导致乐观结论；本协议禁止将“碰到一个异常日”扩成整个区间正确。

## 6. 配对不确定性与多重比较

拟固定 2000 次分层 case bootstrap，随机 seed=20260927。分为 12 层：Normal、五个 Single 形态、六个 Multi 场景。每层有放回抽取原层大小的案例，同一抽样索引用于 N/V 及所有指标。三轴、逐日、多事件不得当作独立抽样单位。

每次必须重新聚合 TP/FP/FN、成功/负轴计数、正轴 Affiliation 和 IoU 充分统计量，再计算指标与 V−N 差；不能直接平均每例 Point F1。抽到相同 case 多次必须保留次数权重，不能放进 case_id 字典后去重，否则 bootstrap 错误。拟用 NumPy `quantile(method="linear")` 的 2.5%/97.5% 分位数作为描述性 95% 区间。无有效分母的重采样项记 N/A，报告无效次数及有效区间所用次数。

两个主任务分别报告点估计和区间，不从其中一个不含零推导“全面优于”。这些逐指标 95% 区间不是同时置信区间，本轮不预设跨任务或大量分组的显著性胜出声明。分组以描述为主；若以后需要假设检验及多重比较校正，须在查看确认结果前另登记统计方案。

区间只反映当前合成案例抽样变化，条件于已采集的一次模型输出；不覆盖服务版本漂移、提示选择不确定性、绘图变化或真实 GNSS 的生成失配。300 例与 2000 次重采样是可控预算设定，没有做功效分析，不能声称能检出任意小差异。

## 7. 成本、结果使用和停止条件

单列工程预检、图像渲染、数值推理（首例冷启动与后续）、视觉传输、评分与 bootstrap 耗时。记录逐请求 tokens 和金额可得性，usage 缺失为未知，不填零；并发墙钟与请求耗时总和分别报告。模型输出来自同一预定运行窗口，但不能据此认为与旧开发 V 同期。

无论结果好坏，封存完整确认报告和全部失败。确认后不基于其错误改阈值、改提示再在同一批数据上宣称独立确认；如需要研发改动，该批数据将成为已见材料，后续必须另立研究版本及新确认集合。

允许得出“冻结数值与视觉方法在该合成分布上的定位能力及取舍”。不能得出真实滑坡预警、现场误报率、通用 Agent 优势，亦不能用同分布新随机种子替代跨分布或现场验证。P7b 的主指标 Gate 仍未通过，不因此自动复活组合路线。

## 8. 正式执行前 Gate

1. 新确认包装器的命名空间派生、配额、无曲线筛选、跨集合重复检查及新数据 ID 验证通过。

3. 发送前账本、中断恢复、失败不重发、输出不可覆盖、请求预算与凭据不落日志通过 fixture。
4. 评分用重复案例权重重算；bootstrap 对重复抽样、失败、Normal-only、重叠 Range 和配对索引一致性通过人工验收。
5. 输入、truth、图片、方法/指标源码和依赖哈希形成正式登记文件；完成无真值推理路径测试。
6. 完成固定 12 次 Pilot 外预检；检查只涉及传输、契约和完整性，不看确认成绩调参。
