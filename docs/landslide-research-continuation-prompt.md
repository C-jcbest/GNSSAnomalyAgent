## 二、研究定位与必须保持的语义

当前主问题是：**在噪声、缺测、平台、弱运动和复合活动条件下，如何可靠确认长期 GNSS 可观测持续位移，并描述活动内的加速、近似匀速和减速；视觉和数值证据各自在什么条件下有价值？**

保留三个可检验问题，必要时基于新证据收缩或修订：

1. 活动层：固定后续阶段头时，视觉、数值及协同候选／确认机制如何改变弱活动召回、平台误报和边界质量？
2. 阶段层：活动遗漏、错误确认、活动内错分、原生弃判和支撑过滤分别造成多少损失？加入视觉是否提供强数值基线无法获得的净收益？
3. 可靠性：这些结论在独立背景、未见形态、不同噪声／缺测、固定绘图扰动和重复推理下是否保持，代价是多少？

任务定义必须一致：

- 先依据原始位移确认持续活动，再在确认内部细分阶段。位移仍平稳、起止待定、缺测或仅导数提前响应时，不赋确定阶段。
- A/S/D 指速度大小的演化。N/E/U 正负方向不是加速／减速；缓慢是强度，不能与 A/S/D 机械并列为互斥阶段。
- S 同时需要可辨识的持续非零运动和近似恒速证据。平台、低速、噪声底、小加速度或“有有限速度估计”均不足以独自支持 S。
- 区分潜在过程真值、观测可辨参考、模型原生预测与最终支撑掩码。参考不自动复制待测方法的 61 日可用范围，也不根据预测补类或改边界。
- 区分可观测活动与滑坡物理归因。单曲线上的平滑仪器漂移和坡体缓变可能不可区分；不能仅按生成场景把可见缓变当稳定负例。
- 图、JSON、CSV 和评分使用一致的活动范围、时间坐标和缺测语义。`unreviewed`、参考 `unknown`、预测弃判与缺测分别登记。
- 当前全记录图和居中导数属于离线回顾识别。在线预警、未来位移预测及失稳时刻预测不进入本轮核心完成标准，也不写成已经验证的收益。

融合或视觉优势是待检验假设。若强数值方法已足够，或视觉只在部分情景有价值，应据此选择最终方法和论文主张。

## 三、当前优先路线与阶段验收

### 阶段 A：核对现状，停止重复的开发搜索

检查最近运行台账、输入／源码／参考哈希、评价分母及原始结果，确认当前配置和未完成事项。整理历史实验的因素、同期控制、失败、全部重复结果和保留／放弃理由，不将不同轮控制拼成统一排行榜。

验收：形成有产物路径依据的状态表；明确正式结论所缺的证据；更新当前路线入口。已有低收益提示与窗口路线进入保留负结果状态，除非新证据给出不同机制和可区分实验。

### 阶段 B：优先补参考、类别支持与真实资料可用性

1. 复用并完善无预测色带的活动／阶段复核包。正式端到端参考要独立审查活动，再审查阶段；只在作者活动内部独立标阶段，仍是条件阶段评价。
2. 优先由具备领域背景、未见待测预测或生成真值的复核者独立标注，记录身份、资格、材料暴露、输入版本和裁决。两名复核者及仲裁是优选；不足时如实披露，不能把新会话 AI、空模板或自动导数规则称为独立专家。
3. 补充训练／验证中的可辨恒速、弱运动、活动后平台、加速后减速、再活动、方向变化、阶跃、相关漂移、缺测和截断。补支持不等于强行补标签；噪声下不可辨段允许未定，不挑最好看的记录。
4. 审查已有 Oak Ridge 数据线索（`https://doi.org/10.5281/zenodo.11511667`）：核验许可、文件、单位、采样、坐标、缺测与场地信息，再判断能否用于案例或评分。两个测站同属一个滑坡，不能作两个独立场地；没有可信参考时只做可用性和定性分析。
5. 区分同生成家族新种子与未见机制／背景。按完整记录、背景或场地划分，同轨迹变体及同场地关联站点不跨独立组。

验收：交付实际数据审查结果、类别／可判性支持表、标注来源及质量报告，并明确是否具备正式比较条件。样本量根据独立组、目标区间精度、试点方差与预算确定，不把连续数万日当独立样本。

若领域复核人员或外部数据暂不可获得，先完成可自主完成的数据审查、协议、复核包、仿真机制恢复实验和论文整理，明确哪些结论仍待外部输入。生成过程标签只能支撑相应机制恢复问题；同会话 AI 观测标签仍只能支撑开发一致性。不得用这些替代物假装正式观测参考已完成。

### 阶段 C：在训练／验证上选择最小方法并冻结

依据阶段 B 的支持情况，复用现有强数值实现、视觉候选与评价器，筛选少量有机制依据的候选：

- 固定确认器与阶段头，比较数值候选、视觉候选及候选并集，先报告候选覆盖上限及成本。
- 固定候选与阶段头，比较数值确认、视觉确认、同图加入同源数值证据的协同确认；必要时保留候选直接输出作为无确认消融。
- 固定活动输出比较规则、XGBoost 与视觉阶段头，拆分内容错误和最终支撑损失。参考活动范围只作诊断上限，不参加公平端到端主排名。
- 针对跨转折整段赋类、D→A/S、恒速证据不足等问题，先检查更简单的稳健分段或数值方案是否足够。没有明确机制与独立验证路径，不引入复杂智能体或更多模型调用。

每项候选先记录不足、证据、机制、与近邻差异、简单替代和证伪条件。每轮只改变可归因的因素；图数量、令牌、训练机会或提示说明不等时如实列明。

验收：依据训练／验证选择规则确定最终方法，冻结数据划分、参数、模型、提示、绘图、候选生成、解析失败策略、重复次数和评价协议。完整内 31 日补充只能作为待验证候选，不因当前单记录开发收益直接成为主方法。

### 阶段 D：正式比较、可靠性及失败分析

满足方法与协议冻结、测试参考隔离和运行预算确定后，按登记协议开展独立评价。测试可交由隔离的标注／评分流程处理，方法开发者不得利用测试内容反向选方案。封存测试不够支持类别或研究问题时，记录缺口并另建评价批次；不能反复查看测试后补样本直到显著。

最低对比包按已有实现选择强数值方法、PELT 趋势／分段适配、XGBoost 活动＋阶段、一个可核验的视觉近邻适配及最终候选方法。自然配置和控制输入／预算的配置分别报告。

明确外部方法状态：TAMA 已有任务适配试运行，但仍需共同任务正式评价；AnomaMind 完整链未运行；TCN 跑通作者示例不等于已有 GNSS 分割基线；完整 TSAD-Agents／Refining 代码的可得性要继续核实。讨论最近邻、记录官方实现差异与硬件限制，不能冒称复现或用弱化替代版代表作者方法。仅输出通用异常区间的方法在共同活动层比较；阶段适配接相同阶段头，单独注明。

正式实验包含主要对比、关键消融、细粒度情景、预定重复、独立组统计、失败／弃判与成本。若要声称优于深度时序方法，补足合理训练的同任务基线及调参机会；主张范围随实际比较范围收缩。

验收：所有运行及失败可追溯，主表与细粒度结果使用同一冻结评价器；核心结论有独立证据。没有稳定净收益时保留负结果，选择更简单方法或调整贡献，不继续为了视觉优势追分。

### 阶段 E：持续更新初稿，完成主张核对

从已有工作稿继续写作，与前述阶段并行。先完善任务定义、方法实际实现、数据／标注来源和协议，再补正式结果，最后完成摘要与结论。

为核心主张建立“主张—证据—适用范围—限制”对应关系。分别说明成熟方法复用、任务适配、工程集成、实验发现及经验证的新方法贡献。活动—阶段拆分、可审计网页、schema 成功和负结果积累本身不自动构成方法创新；若定位为基准或可靠性研究，仍须证明问题、协议和实证发现相对近邻的研究价值。

验收：论文含摘要、引言、相关工作、任务与方法、实验、讨论、局限和结论，全部数字可回溯，引用可核验，开发与正式结果明确区分。只有仿真时限定受控仿真结论；没有经过验证的贡献时如实报告，不包装成创新。

## 四、评价与统计的统一约束

- 活动保留不做 point adjustment 的逐日 P/R/F1、事件一对一匹配指标及边界误差。当前已有 IoU≥0.3 口径；新主阈值与敏感性阈值须在测试前确定，变化另建评价版本，不重写旧分数。
- 事件定义、相邻告警合并、未知桥接、缺测处理和可评价域必须公开。不能借桥接或未知区域产生虚假的连续活动。
- 阶段报告 A/S/D 逐类与 macro-F1、端到端和条件阶段成绩。第一层漏检引起的阶段漏判以及已知非活动日上的阶段误报计入端到端结果；缺类子集明确标记，不伪装为完整三分类指标。
- 已知参考上的预测弃判和契约失败保留在完整分母，并报告失败率、覆盖及风险。参考未定日上的确定输出另列，不自动当 FP；未知和缺测不当稳定真负例。
- 弱活动、平台、恒速、复合转折、阶跃、漂移、长缺测及边界截断分别分析。报告记录数、事件数、各类支持、可评分日和未定暴露，避免小类 macro 权重掩盖其他类别损失。
- 非活动日期虚假加速、误报事件和负暴露明确分母；按可核验定义报告每站年误报，不将既有“接触负日事件率”默称纯假事件率。
- 按完整独立记录／背景／场地做配对统计或分组 bootstrap。重复调用不是新增独立记录，日历点不是独立样本；组数不足时以描述性结果及逐组差异为主，不给虚假的精确显著性。
- 主指标、次指标、重复次数及多重比较处理预先登记。硬区间输出不伪造连续分数计算 AUC，不以测试 Best-F1 或最好一次调用替代冻结结果。
- 契约合规、引用覆盖、重复稳定性、辅助估计可用性与内容正确性分别报告，不能相互替代。

1. 先检查 Git 工作区已有修改，保护用户工作。允许必要重构并完整迁移可控调用方，不做无关清理；不得破坏原始数据或删除冻结历史。
2. 优先复用标准库、现有依赖、评价器及批量脚本。确有编排缺口才建立薄的统一入口，避免再造通用研究框架；验证入口可发现失败、恢复安全的本地步骤并汇总结果。
3. 每轮记录研究假设、协议、数据／标签／源码哈希、环境、种子、模型版本、提示、实际输入图、原始回答、预测、配置、耗时、token、费用可得性和失败。旧目录拒绝覆盖；新版本与失败版本都保留。
4. 隔离观测、预测、生成真值与评分参考。网页和送模内容不含真值阴影、潜在过程、阶段名称或泄漏类别的文件名。
5. 批量付费调用前评估价值、请求上限、token 上限、可得单价和停止条件。已有授权预算内直接推进；预算或敏感内容外传权限确实缺失时，准备具体可审阅方案再询问。不能凭本地配置存在认定无上限授权。
6. 保存请求失败，禁止无限自动重试或挑成功重跑。工程修复可另建版本并验证旧预测是否改变；再次付费确认必须是新登记运行，不覆盖冻结失败。
7. 测试与风险匹配，验证业务语义、隔离、边界、缺测、契约失败和评价算术。修改后通读完整受影响函数及调用处做可读性复查。工程测试通过、研究假设获支持和正式有效性分别记载。
8. 图表从实际数据自动生成，保存 CSV／JSON 与可用于论文的图文件；实际送模图和事后解释图明确区分，不补造模型内部思考。HTTP／DOM 脚本通过不写成真实浏览器渲染验收。

## 七、自主迭代、停止条件与交付

每轮完成：明确假设 → 冻结必要因素 → 实际实现与运行 → 保存全量结果 → 分析收益／损失／成本 → 判断支持或否定 → 更新路线和论文。每阶段产出实际文件，不能只留下待办事项。

继续迭代的依据是存在明确机制、证据支持和可证伪实验。若独立数据支持研究假设且贡献达到预定验证要求，转入最终整理；若连续受控试验没有稳定收益，停止该分支，保留负结果并收缩主张。不要把“自主完成”解释为永不停止，也不要完成一次实验就宣布整个研究结束。

需要领域复核、外部许可或额外预算时，明确阻塞的是哪项结论，给出已准备的具体材料和最小输入要求，继续其他不依赖它的授权工作。不得为了避免询问而制造专家身份、参考标签或独立性。

最终交付：

1. 研究定位、近邻差异及经证据支持的贡献／负结果。
2. 有规范入口、必要测试和可追溯配置的实验代码。
3. 全部正式与开发原始结果、失败台账及数据／参考来源。
4. 主要对比、消融、细粒度、可靠性、失败／覆盖／成本分析及论文图表。
5. 与结果一致的完整论文初稿和可核验参考文献。
6. 环境、数据准备、运行命令、图表映射与复现限制说明。
7. 完成条件逐项核对：已完成、未验证、缺外部输入和不成立的假设。

只有研究问题、可信评价、代表性比较、机制消融、可复现结果和核心主张证据均满足时，才能报告研究基本完成。若仍缺独立参考或经验证的研究贡献，报告实际成果与缺口，不把工程完备或完整正文等同于可投稿实证成果。

**现在从最新状态与产物核对开始，优先补可信共同参考、恒速与困难情景支持、未见记录和真实资料审查；复用已完成实验及论文底稿，推进方法冻结与正式验证。不要重复已经完成的支撑消融，不再默认在已暴露批次追加提示或窗口搜索，不预设视觉／融合胜出。**
