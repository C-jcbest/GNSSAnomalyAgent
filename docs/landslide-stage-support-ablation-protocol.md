## 研究问题和固定因素

检验**最终支撑门控**的窗口取舍，区分“原生内容已经未知”和“原生类别有输出、却被61日支撑过滤”的瓶颈。复用冻结三阶段头原生输出：规则、保存的XGBoost、视觉；全部12条、21活动内部和逐日观测不变。核对观测、日历、活动内容哈希与审计源完全一致。最大新增模型调用0，无重新训练、调概率阈值、改提示、候选、schema或活动边界。

这不是三窗口分类器的公平重训对比。规则及XGBoost原生内容仍来自既有特征，视觉原生内容仍来自既有请求；只换最终可用性掩码。若原生unknown，三个窗口再充分也不能产生确定类。有限速度仅是S支撑的必要条件，不证明非零且恒速；A/D的切向符号也不自动覆盖原生语义。

## 五个配置

| 配置 | 规则 | 所检验的因素 |
|---|---|---|
| fixed_61 | 原61日支撑 | 原冻结基线；必须重现全部旧final输出 |
| fixed_31 | 31日支撑 | 缩短最终支撑窗口的新增与损失 |
| fixed_91 | 91日支撑 | 延长最终支撑窗口的新增与损失 |
| fallback_31_contained | 原生类别在61窗支撑充足则沿用；不足时仅允许完整落在同一活动内部的31窗 | 有限支撑补充，不改变原有61窗输出 |
| contained_61 | 61窗支撑充足，且整个窗落在同一活动内部 | 保守边界门控的覆盖代价 |

每个确定类均要求中心有原观测并位于冻结活动；S需有限速度，A/D还需同一选定窗的有限切向加速度。不混用31窗速度和61窗切向。半开窗[center-half, center+half+1)须包含在同一冻结活动[start,stop)内部；不跨缺测改变日历。观察守卫沿用冻结缓存，不再拟合。

审计发现31窗新增112个切向可用日中完整活动内仅60日，且同时损失386日，支持分别测试固定短窗和受约束补充，而不是直接替换61窗。fallback保留原61窗的跨边界估计，所以它仅检验新增支撑；contained_61单独检验边界弃判。短活动和首尾截断可能没有任何完整内窗，必须显示结构性弃判，不移动活动边界以保留输出。

三对窗的原始切向异号不进入弃判或分类规则。缓存缺少误差尺度；尚无不依本批标签的物理显著阈值，近零异号不能当确定冲突。未来冲突规则必须独立登记和校准，不能逐批试阈值追macro-F1。
