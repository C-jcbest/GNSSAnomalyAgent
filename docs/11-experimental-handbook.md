# 数值与视觉方法的 GNSS 异常定位实验

> 实验方法手册 · 2026-09-27 · 受控合成数据研究。P1～P7b 开发实验已完成；P7b 两项主指标均未通过继续 Gate，独立确认未启动。本文采用论文的研究问题、方法、实验设置与有效性讨论结构；冻结参数和历史结果仍以对应版本协议为准。

## 摘要

当前开发进展见 [P8a 视觉 Range 全局与局部对照](15-p8a-visual-range-context.md)：60 例筛查及用户指定的完整 Pilot300 测试均已完成，统一 8192 tokens。局部图提高日 IoU，但主 F1 未超过单轮；原 60 例 Gate 未通过的结论保留。P7b 历史结果保留，独立确认数据仍未使用，尚未实施 Agent。

本研究比较数值方法与多模态大语言模型在 GNSS 三轴日序列中定位异常日期及活动区间的能力。固定 300 个合成开发案例、统一观测输入和评价协议，分别运行四个数值基线及两版纯视觉提示。实验保留精确日、容差日、距离关联和区间重叠等不同评价视图，避免将单一指标理解为全面能力。当前开发证据表明，数值与视觉方法存在不同的覆盖和定位特点，但直接合并预测会增加误报。随后 60 例固定候选复核减少了过报，但损失正确候选，两项主指标均下降；因此本版未进入独立同分布合成确认。本研究不预测滑坡、不判断异常原因，也尚未验证真实站点或 Agent 的性能。

**关键词：** GNSS；时间序列异常定位；Point；Range；视觉语言模型；Affiliation；可复现评价。

## 1. 研究问题与文献定位

### 1.1 研究问题

- **RQ1：基础定位能力。** 在相同三轴输入下，数值与纯视觉方法分别能多准确地定位异常日期与活动区间？
- **RQ2：评价偏好。** 精确定位、容差定位、区间关联、边界重叠和误报负担是否给出一致的方法排序？
- **RQ3：固定复核价值。** 对相同候选集合增加一次有界的视觉复核，能否减少错误预测，同时维持有用的召回并承担合理成本？

RQ1/RQ2 已有开发结果；RQ3 尚待实验。以上为研究问题，不预设数值、视觉或组合哪一种更好。

### 1.2 与已有研究的关系

[VisualTimeAnomaly / TSAD-Agents，WWW’26](https://arxiv.org/html/2502.17812v2)按异常粒度组织实验，并研究工具检测与模型检查的分工。本项目借鉴分任务评价和依据能力实验设计后续流程的写法；三轴 GNSS 生成公式、Point 起点语义与开发配额均是本项目设定，不是对其全部基准的复现。

[VLM4TS](https://arxiv.org/html/2506.06836v2)采用候选定位与上下文验证两阶段。它的第一阶段使用预训练视觉编码器；本项目拟复用数值与独立视觉候选，因此属于方法思路改造。其 F1-max 结果也不能与本项目冻结阈值后的 F1 数字直接比较。

[Local Evaluation](https://arxiv.org/abs/2206.13167)提供基于距离的 Affiliation 指标；[指标分类综述](https://link.springer.com/article/10.1007/s10618-023-00988-8)说明指标包含不同评价偏好。[严格评价研究](https://arxiv.org/abs/2109.05257)指出 point adjustment 可能夸大成绩。本项目据此并列报告多种指标，保留未经真值修正的预测，不使用“命中一点便把整段改成正确”的后处理。

## 3. 任务定义与数据生成

### 3.1 观测模型

第 $i$ 个案例在日 $t$、轴 $c$ 的观测为：

$$
O_{i,t,c}=P_{0,c}+B_{i,t,c}+\epsilon_{i,t,c}+D_{i,t,c}+A_{i,t,c}.
$$

$P_0=(0,0,0)$ mm；$B$ 为正常周期背景，$\epsilon$ 为独立高斯白噪声，$D$ 与 $A$ 分别是生成器记载的两组注入贡献。检测输入使用带符号位移 $X=O-P_0$。这些生成来源不等于能够从观测推断出的物理原因。

$$
B_{i,t,c}=a_c\sin\left(\frac{2\pi t}{365.25}+\phi_{i,c}\right)
+b_c\sin\left(\frac{4\pi t}{365.25}+\psi_{i,c}\right).
$$

按 N/E/U，$a_c$ 为 1.0/1.0/1.5 mm，$b_c$ 为 0.25/0.25/0.5 mm，白噪声标准差为 0.5/0.5/1.0 mm。相位和噪声 seed 独立派生。当前没有缺测、相关噪声或长期正常速度项。这些数值用于固定受控条件，不代表现场 GNSS 精度。完整模型见 [P1 协议](02-p1-normal-model.md)。

### 3.2 五种事件及活动语义

下表令 $s,e$ 为活动起止索引，$a$ 为带符号幅值，$L=e-s+1$。公式表示注入单轴的贡献 $f_t$；未列出的活动前贡献均为零。

| 生成形态 | 贡献与活动定义 | 检测任务 |
| --- | --- | --- |
| Spike | $f_s=a$，其他日为 0 | Point：仅 $s$ |
| Step | $t\ge s$ 时 $f_t=a$ | Point：仅 $s$，不标整个尾部 |
| Slow Trend | $t\ge s$ 时 $f_t=a\min((t-s)/(L-1),1)$ | Range：$[s,e]$ |
| Acceleration | $t\ge s$ 时 $f_t=a\min((t-s)/(L-1),1)^2$ | Range：$[s,e]$ |
| Transient Shift | $s\le t\le e$ 时 $f_t=a$，随后归零 | Range：$[s,e]$ |

Slow Trend/Acceleration 持续 90 日，Transient 持续 14 日。Spike 与两种长期事件终值的绝对幅值按 N/E/U 为 4.5/4.5/9 mm；Step/Transient 为 3.75/3.75/7.5 mm，符号独立分层。单个活动区间落在索引 60～304 内。多事件按六种冻结场景叠加，详见 [P2/P3 协议](04-planned-methods.md)。以上生成知识只供研究说明，不进入模型提示。

例如 Step 在索引 120 发生，正确 Point 是 120；120～364 的稳定 offset 不能作为正确 Range。Slow Trend 在 100～189 演化，190 以后保持的偏移也不计活动。临时偏移按整段 Range 报告，不额外把两端当作 Point。长期事件首日贡献恰为零，这是真值边界的生成定义，不保证观测在首日即可分辨。

### 3.3 输出契约

每个方法、案例、任务保存一行结果。Point 输出逐轴日期集合；Range 输出逐轴闭区间集合。预测不含异常类别，错误轴和错误时间均影响成绩。

```json
{"case_id":"case_0001","method":"example","status":"success","predictions":{"N":[],"E":[105],"U":[]}}
```

```json
{"case_id":"case_0001","method":"example","status":"success","predictions":{"N":[[160,235]],"E":[],"U":[]}}
```

以上只是格式示例，不是真实结果。Point 与 Range 分文件、分任务验证。当前 Range schema 可以表达单日区间；任务提示仍要求报告持续活动，长度本身不自动成为 Point 类型判断。重叠区间在评分时转为日期并集，不重复计算同一天。缺失行或方法失败保留在案例全集中。

### 4.1 Development Pilot

| 分层 | 数量 | 用途 |
| --- | ---: | --- |
| Normal | 30 | 数值阈值校准及开发误报检查 |
| Single-event | 120 | 五种形态各 24；每种 N/E/U 各 8，每 type×axis 正负各 4 |

| 总计 | 300 | 所有历史方法使用相同输入 |

固定数据身份为 `pilot-v1`，生成器为 `event-v6`，主 seed 为 20260925。分层搜索只使用 type/axis/sign/scenario 元数据，不按曲线可见性、噪声强弱或算法表现选择案例。GT 始终来自原 `events[]`；评分按任务确定性派生日期集合，不再人工保存另一套标签。

### 4.2 开发与独立确认

当前 300 例已全部用于方法选择与提示分析。将其中 60 例用于小规模 P7b 只会降低开发成本，不会使其余 240 例变成独立测试。

独立确认拟使用相同配额的另 300 例，维持生成公式与幅值。方法和提示冻结后，才使用预先登记的新 seed namespace 生成，核对 case/component seed 及移除身份字段后的数值输入哈希不与开发集重复。确认集的 Normal 不再校准阈值；确认结果不反馈改参数。如果需要继续选择方案，则另外建立验证集并另留最终测试，明确记录用途。

### 4.3 信息流与访问边界

允许的信息流为：**input → 数值检测 / 无标签图像 → 预测归档 → 独立读取 truth 评分**。网页真值叠图仅供研究人员检查，不能截图给检测模型。方法请求不包含分层、类型、位置安全区、幅值/时长或 GT 数量。

P6/P7a 推理已按输入哈希独立检查。P5 历史运行器会在预测前用 truth 做完整性校验，但其检测/校准函数不消费异常标签。新独立推理入口需要把这些校验与评分隔离，加载 P5 冻结阈值；该入口目前尚未实现。原始数据、模型回复和凭据只保存在本地，不入 Git。

## 5. 基线与视觉设置

### 5.1 Numerical：四个独立基线

| 方法 | 直观含义 | 当前实现与限制 |
| --- | --- | --- |
| SR，Spectral Residual | 从频域背景中突出局部异常显著性 | 简化谱残差，频谱平滑宽度 3；不是完整 SR-CNN |
| PELT | 用分段拟合发现均值变化位置 | L2 代价、最短段 3 日、jump=1；不适合表示单日尖峰 |
| Matrix Profile | 比较一个子序列与其他子序列的近邻距离 | z 标准化 self-join、30 日窗；只代表该配置 |
| Rolling Theil–Sen | 用窗口内两两斜率的中位数估计稳健趋势 | 30 日窗，取斜率绝对值作为分数 |

MP 与 Theil–Sen 的窗口起点 $j$ 对应分数映射到右中心日 $j+15$，不把整个窗口涂成异常；无分数边缘日为零。超过阈值的连续日期形成 Range，不人工延长或合并间隙。所有方法逐轴运行。

SR/MP/Theil–Sen 使用 30 个 Normal 案例的逐轴最大分数分布，取经验 95% 分位数校准阈值；这不等于独立数据有严格 5% 误报保证。PELT 从预定 beta 候选中按 Normal 报警规则选择。算法参数、公式与精确阈值以 [P5 协议](06-p5-numerical-baselines.md)及 `configs/p5-frozen.json` 为准。开发规则选出的主数值方法是 Point SR、Range Theil–Sen；其他两项结果继续保留。

### 5.2 Visual：只看图的模型

两版均使用 `qwen3.8-flash`，显式关闭 thinking，temperature=0，max_tokens=512，4 个并发 worker。输入为同一份 1800×1200 N/E/U 三联图，横坐标索引为 0～364，各轴按固定 renderer 自动缩放。模型只看图和任务说明，不接收数值数组、数值检测候选或真值。

每案例 Point/Range 各一次逻辑请求，每次最多一次尝试，严格检查 JSON Object 的 N/E/U 结构。`visual-v1` 是原提示；`visual-semantics-v2` 只增加明确的 Point/Range 活动语义，复用原图片、传输参数和解析器。详细请求与冻结记录见 [P6](07-p6-visual-baseline.md)和 [P7a](09-versioned-comparison.md)。无效格式不能事后修补成成功，温度为零也不代表服务权重与输出永久确定。

## 6. 评价指标：计算、含义与局限

### 6.1 TP、FP、FN 与 micro F1

对某个 case×axis，记真值日期集合为 $G$，预测为 $P$。在精确日评价中：

$$
TP=|G\cap P|,\quad FP=|P\setminus G|,\quad FN=|G\setminus P|.
$$

TP 是正确报出的阳性日期，FP 是错误报出的日期，FN 是漏报的阳性日期。Point 只把目标起点作为日期；Range 逐日视图把区间展开为全部活动日期。全局先汇总所有案例和轴的 TP/FP/FN，再计算：

$$
\mathrm{Precision}=\frac{TP}{TP+FP},\qquad
\mathrm{Recall}=\frac{TP}{TP+FN},\qquad
F_1=\frac{2TP}{2TP+FP+FN}.
$$

Precision 回答“报出来的有多少正确”，Recall 回答“真实目标找到了多少”，F1 是二者的调和平均。例：TP=3、FP=1、FN=2，则 Precision=0.75、Recall=0.60、F1≈0.667。正常日期占比大，因此不使用 Accuracy 概括异常检测能力。

**空分母约定：** 总体存在 GT 但没有预测时，Precision/F1 记 0。无 GT 的分组在新论文导出中 P/R/F1 为 N/A，仍报告报警量与 FAR；历史 P4 代码在全空任务返回 0 的兼容行为不用于解释正常组识别能力。

### 6.2 Point 精确日与 ±3 日

精确日是 Point 主指标；例如 GT=100，预测=101，则产生一个 FP 和一个 FN。±3 日视图对同一轴满足 $|\hat t-t|\le3$ 的日期构造候选匹配，求最大数量的一对一匹配，再按匹配数计算 TP、未匹配预测 FP、未匹配真值 FN。

例如 GT={100,103}、预测={101}，即使两个真值都在容差内，也只有 1 TP、1 FN。同一预测不能重复得分，也不能匹配其他轴。±3 日衡量邻近定位，不能表述为精确日期识别率；这是本项目固定的辅助容忍度，不是普遍标准。±1/7 日仅为完整敏感性附表。

### 6.3 Range Affiliation：距离关联

Affiliation 将真值事件周围的时间分配到局部关联区域，基于预测与真值之间的距离和局部参照分布构造 precision/recall。它衡量预测是否靠近对应活动，而非简单的日期交集比例，因此可能在边界重叠有限时仍有较高分数。算法数学细节以 [原论文](https://arxiv.org/abs/2206.13167)为准，项目使用锁定 commit 的上游实现，不自行替换公式。

实现先将闭区间转为 365 日布尔向量，再转为上游半开区间；例如 `[100,189]` 对应 `[100,190)`，时间域为 `[0,365)`。每个有 Range GT 的 case×axis 分别得到 $p_{ic},r_{ic}$ 和 $f_{ic}$：

$$
f_{ic}=\frac{2p_{ic}r_{ic}}{p_{ic}+r_{ic}},\quad
F_{\mathrm{Aff}}=\frac{1}{|\mathcal A^+|}\sum_{(i,c)\in\mathcal A^+}f_{ic}.
$$

$\mathcal A^+$ 为固定 GT 正轴集合；Pilot 中有 199 个。没有预测或方法失败的正轴按 0 分计入，不能删掉。宏 P、宏 R 也分别平均；**宏 F1 不等于宏 P 与宏 R 再求调和平均。** 负轴不进入 Affiliation，而是另外评价 FAR。

### 6.4 Range 逐日 IoU 与全轴 F1

对一个 GT 正轴，以活动日期并集计算：

$$
\operatorname{IoU}_{ic}=\frac{|G_{ic}\cap P_{ic}|}{|G_{ic}\cup P_{ic}|},\qquad
\operatorname{MeanIoU}=\frac{1}{|\mathcal A^+|}\sum_{(i,c)\in\mathcal A^+}\operatorname{IoU}_{ic}.
$$

GT 为 `[100,189]`，预测为 `[110,190]`，交集有 80 日、并集有 91 日，所以 IoU=80/91≈0.879。空预测的正轴为 0。这里计算的是每轴**全部区间的日期并集**，不是事件配对后的平均 IoU，也不设 tIoU≥0.5 的匹配门槛。

正轴 Mean IoU 对每个正轴等权，反映覆盖与边界重叠，但不惩罚负轴报警。因此同时给出全部案例×三轴×日期的 micro F1；后者计入负轴 FP，长活动段也有更大计数权重。两者应并列解释。

### 6.5 FAR、Normal 诊断与执行成功率

令 $V_i$ 表示某方法在该任务的案例输出合法，$\mathcal A^-$ 为该任务 GT 为空的轴集合。主 FAR 为：

$$
\mathrm{FAR}=\frac{\sum_{(i,c)\in\mathcal A^-}V_i\,\mathbf1[|P_{ic}|>0]}
{\sum_{(i,c)\in\mathcal A^-}V_i}.
$$

它回答“成功处理的任务负轴中，有多少轴至少报了一次警”。不是 FP 日数比例，也不是 30 个 Normal 案例的误报率；一次报警和很多次报警在这个指标上都只算一个报警轴。Pilot 若全部执行成功，Point/Range 分母分别为 576/701 个负轴。

另外对 30 个 Normal 报告成功轴 FAR、预测日期总数、案例失败率；Normal 的三轴最多构成 90 个有效轴。这些量区分“报警涉及多少轴”和“报警持续多少天”。执行成功率为 $\sum_i V_i/N$，按案例×任务计算，不能把 HTTP 200 等同合法输出。

方法失败时，正轴按空预测保留 FN 或零分；负轴不充作正确无报警，退出 FAR 有效分母并单独记录失败。全轴逐日计数同样使用空预测保留阳性漏报，不能据失败时 FP 较少评价方法优秀。不同方法成功分母不同时，报告原始计数及共同成功集合的辅助结果，主表仍保留全部案例。

### 6.6 主表应如何阅读

| 任务 | 主指标 | 补充指标 | 不能推出的结论 |
| --- | --- | --- | --- |
| Point | 精确日 micro P/R/F1 | ±3 日、FAR、执行成功率 | 高容差分数不代表逐日精确 |
| Range | Affiliation macro P/R/F1 | 正轴 Mean IoU、全轴日 micro F1、FAR、成功率 | 高关联分数不代表边界准确 |
| Normal | FAR、报警量、失败率 | 按轴及案例计数 | 无阳性组不报告“正常 F1” |
| 工程 | 逻辑请求数、实际尝试、tokens、耗时 | 缓存复用、失败原因、金额可得性 | 少增量调用不等于完整流程免费 |

全部结果来自开发 Pilot。完整八行方法×任务表及冻结产物见 [多版本比较](09-versioned-comparison.md)；下表用于解释指标差异，不改变历史选择。

| --- | ---: | --- | ---: | ---: |
| SR / Point | 0.5518 | ±3 日 F1=0.5831 | 0.2101 | 1.0000 |
| Visual v2 / Point | 0.0837 | ±3 日 F1=0.4770 | 0.3077 | 0.9900 |
| Theil–Sen / Range | Aff 0.9345 | 正轴 IoU=0.3398 | 0.1954 | 1.0000 |

视觉 v2 的长期边界有改善，但 Point 精确定位仍弱。SR 对 Spike/Step 精确命中分别为 302/302 与 15/141，PELT 对 Step 为 91/141，说明总体排名不能替代分组能力分析。新版视觉与数值直接取并集会显著增加误报，详见 [全程审查](10-experiment-audit.md)。

## 8. P7b 固定候选复核实验规格

### 8.1 目标与四个条件

本节为已执行的 `candidate-review-v1` 规格。仅检验保留/删除是否有价值；配置、提示与源码在正式调用前冻结。完整结果见 [P7b 协议与结果](12-p7b-candidate-review.md)：Point 精确 F1 从 U 的 0.3512 降至 C 的 0.2955；Range Affiliation F1 从 0.8498 降至 0.7597，未进入独立确认。

| 条件 | 输入与处理 | 在比较中的作用 |
| --- | --- | --- |
| N | Point SR；Range Theil–Sen | 冻结数值对照 |
| V | 独立语义 v2 图像检测 | 纯视觉对照 |
| U | N 与 V 候选的并集 | 复核前的精确对照 |
| C | 同一 U 候选加图像，由模型 keep/drop | 检验复核的增量收益 |

C 与 U 共用完全相同的上游预测，不能为 C 重跑 V 或删掉难例。四条件都在相同案例、任务、指标上评分。PELT/MP 保留历史基线；本阶段不加入 SR+PELT ensemble。

### 8.2 开发子集与独立确认顺序

已从已知 Pilot 按元数据确定性取 60 例：6 Normal；30 Single（每种形态×轴×符号各 1）；24 Multi（每 scenario 各 4）。层内按固定的 case_id 顺序取首例，不查看曲线或按预测结果挑选。这个子集是开发筛查，比例与 300 例略有不同，不能直接把其汇总分数与完整 Pilot 排名比较。

本次开发复用已归档 N/V 以控制成本，明确其请求时间差；确认阶段则运行冻结参数的 N 和同期 V，再生成 U/C，完整记录调用时间。先在开发子集完成可靠性与增益检查，锁定版本后才执行独立 300 例确认。当前没有创建这份确认集。

### 8.3 候选构造与模型可见信息

Point 候选按 `(axis,day)` 精确去重；Range 按 `(axis,start,end)` 精确去重，不先把交叠区间合成大区间，保留删除单个区间的可能性。按 N/E/U、start、end 稳定排序并分配 ID。相同候选保留所有来源于本地记录，模型请求只给 ID、轴和日期边界，不给方法名或置信度，以减少来源偏好。

模型同时收到原无标签三轴图和任务活动语义。输出采用严格对象 `{"keep_ids":["candidate_001"]}`；空数组表示全部删除。未知 ID、重复 ID、额外字段、解析错误均判该批失败；不能接受新日期、修改轴或修补 JSON。按被保留的原候选重新构造合法 Point/Range 输出。

### 8.4 调用边界与失败策略

已固定使用 qwen3.8-flash、thinking=false、temperature=0。候选按固定顺序每批至多 64 个；每批一次尝试，复核 max_tokens 为 2048，worker 上限 4。上游 V 保留原 512 token 设置，不因复核另调提示。正式运行前 4 次 Pilot 外人工数据工程预检通过，覆盖单候选及 64 候选请求的传输与解析；这不等于准确率或大规模容量保证。若改变响应模式，应另记版本，不覆盖旧 v2。

365 日三轴 Point 最多有 1095 个去重日期候选；Range schema 允许交叠区间，不能用极大连续段数量推导其实际候选上限。两任务统一设每 case×task 最多 18 批、1152 个候选作为工程预算，不截断超限候选；超限直接记失败并调查实现。最多一次尝试意味着没有网络重试或结构纠错调用。空候选且两上游成功时，U/C 都输出合法空集合，C 不调用模型。

**新实验采用严格依赖成功规则：** N 或 V 任一路失败，U/C 都记失败，不将缺失的一路当成功空预测；C 任一批失败，则整例该任务失败，保留原始批次记录。这与此前“视觉失败回退数值”的并集审查诊断不同，必须使用新方法标识重新评分。审查中的并集成绩不直接填进本实验 U 条件。

### 8.5 怎样判断复核价值

Point 记录 U→C 的 TP/FP/FN 变化、删除 FP 数与损失 TP 数；精确和 ±3 日分别重新匹配，不能固定沿用旧匹配。Range 记录日级 FP/TP 的删除量及 Affiliation/IoU 变化；删除一个区间不必然删除所有对应日期，因为其他保留区间可能仍覆盖它。

对 Point，C 只能删候选，因此候选池的精确/容差召回是其可达召回上限；若 U 已缺正确日期，不能期待 keep/drop 恢复。对 Range，keep/drop 不直接优化端点；未来如允许改边界，必须另立方法及对照。

开发继续条件应依据预先登记的主 F1 差值、召回变化、FAR 与成本共同判断，不以单项最佳分数宣布成功。默认只有 C 相对 U 主 F1 提升、同时完整披露漏报代价时才考虑进入确认；与 N/V 的比较仍必须报告。没有通用“合格 F1”，若提升不足或代价过大，允许停止组合路线。

## 9. 重复性、统计与成本报告

### 9.1 不确定性与比较单位

方法在同一案例上的输出成对比较。独立确认拟采用按 Normal、各 Single 形态、各 Multi 场景分层的 case bootstrap；每层有放回抽取相同案例数，同一重采样索引同时用于所有方法。拟固定 2000 次、随机 seed=20260927，对每次重新计算整体指标差，报告 2.5%/97.5% 分位数区间。

这个区间条件于既定合成分布及已经采集的模型输出，不覆盖模型服务漂移、生成模型失配或真实现场差异。无有效分母的重采样项需报告数量并显示 N/A，不能静默删除。不得把三轴、逐日样本或同例多事件当独立样本夸大样本量；bootstrap 分析目前尚未实现。

如果要专门论证提示改动或模型随机性，应另做同期交错的预定重复实验；重复标准差只是重复波动，不是上述案例抽样置信区间。不按某次最好成绩保留模型结果。

### 9.2 成本口径

分别记录预检、N/V 候选生成、图像渲染与 C 复核的调用数、实际尝试、输入/输出 token 和耗时。C 的增量成本为新增复核；完整流程成本还包含 N/V 和图片，缓存不使完整流程免费。API 未给出金额或超时未给 usage 时保留 null/未知，不填零。

当前数值时间含校准与首次 JIT，视觉时间主要覆盖调用阶段，不能据此公平比较端到端速度。新入口应分别记冷启动与稳定阶段，并明确缓存与并发设置。

## 11. 有效性威胁与报告边界

2026-09-28 补充：已完成 [P7b 错误归因与实验链检查](13-p7b-error-analysis.md)，来源/类型/阶段分解仅为事后诊断；[独立 N/V 确认草案](14-independent-confirmation-protocol.md)给出后续 Gate，尚未生成或运行，不改变本手册主指标及 P7b 停止结论。

**内部有效性。** Normal 同时校准和开发评价，提示受 Pilot 启发；不同时间模型版本和响应不完全可控。通过保留全部版本、失败、调用记录和独立确认降低风险，不能宣称已经消除。

**构念有效性。** 生成活动边界与人眼可辨边界不完全一致，永久 Step 和短暂偏移可能具有相似局部形状。多个指标从不同角度测量定位，不把 Affiliation、IoU 或容差 F1 单独等同业务可靠性。

**外部有效性。** 固定白噪声、幅值、时长及场景不覆盖真实 GNSS 条件；同分布合成确认也不能证明现场推广。完整 365 日输入包含未来信息，实验研究离线定位，不研究在线告警延迟。

**结论边界。** 当前可以写“在冻结合成开发集上的能力比较和误差分析”；不能写“验证真实滑坡预警”“Agent 全面优于基线”或“视觉取代数值”。不成功的组合实验也应如实保留。
