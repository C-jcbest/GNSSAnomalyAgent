日期严格递增、相邻均相差一天，无重复日期；五个有效字段无空单元格。data_2/data_4 尾部另有三个始终为空的列，完整保留。标题所写 2015—2025 与实际起始日期不同；文件覆盖是 2016 年 6 月起，并非额外拥有 2015 年观测。

这些只是**发布 CSV 的日历与数值契约**，不证明每天均为独立原始采集，也不证明没有采集缺测、填补或仪器变化。重复值及数值下降只作文件统计，不直接赋静稳、减速或异常标签。未重采样、插值、平滑、去异常或进行单位转换。

单位与字段存在实质冲突：

- 官方 PDF 4.2 节称水平累计位移；表 4/6、5.3.2 和 6.1.2 节按 mm 报告重建误差和约 500 mm 的累计幅度。
- 固定 GitHub commit `d4ab9d9079f3b130e23fcdbaf8dc77de96b6fd2c` 的 data/README.md 和 data_io.py 将 displacement_XY 写为 metres，把 elevation 写为站点地表高程（constant or DEM）。CSV 中 elevation 随时间变化，含接近零值，不能据名称直接认定为垂直位移或绝对地形高程。
- Zenodo 21483154 的 GNSS2 notebook cell 2 直接读取 CSV，不换算位移；cell 6 的原始位移图轴写 m、趋势和随机图轴写 mm、库水位图轴又写 mm。不能根据其中一个轴标签选择换算比例。
- GitHub 数据文档要求上游日尺度重采样／缺测插值并显式提供 metadata 标记，但所取 RAR 只有三个 CSV，未附采集缺测或插值掩码。文档为预发布审稿包，不能把其中的通用 QC 说明当作这三个文件已验证的完整处理历史。

因此不把水平标量扩充成 N/E/U，不把 elevation 当 U，不在无法确认单位下运行现有毫米阈值或移植模型；也不把环境列当作额外独立 GNSS 观测。原始数值图仅用于来源理解，无预测／标签色带。
