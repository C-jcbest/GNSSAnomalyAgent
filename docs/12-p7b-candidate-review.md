# P7b 固定候选复核：开发实验协议与结果

## 1. 研究问题与实验地位

本实验检验：在完全相同的数值与视觉候选集合上，图像模型仅进行保留/删除，能否减少过报，并以可接受的召回损失改善主指标？它是固定流程的开发能力实验，不是 Agent，不是官方 TSAD-Agents 复现，也不预设组合优于独立方法。

设计依据是 [Can Multimodal LLMs Perform Time Series Anomaly Detection?](https://arxiv.org/html/2502.17812v2) 的视觉异常定位与 TSAD-Agents 讨论，以及 [VLM4TS](https://arxiv.org/html/2506.06836v2) 的候选复核思路。VLM4TS 原方法的前级并非本项目的 SR/Theil–Sen；这里是针对 GNSS 模拟任务的简化改造。评价保留 [Affiliation](https://arxiv.org/abs/2206.13167)，同时报告逐日重叠，避免把较宽容的关联分数等同精确边界。完整术语和文献定位见[方法手册](11-experimental-handbook.md)。

## 2. 样本与四个条件

从冻结的 `pilot-v1` 按元数据确定性选取 60 例：6 Normal；30 Single（五种形态 × 三轴 × 正负，每格 1 例）；24 Multi（六场景，每种 4 例）。每层按 case_id 字典序取前若干例。未使用曲线、检测成绩或模型响应选择案例。60 例及其余 240 例均已用于开发，不是独立测试；60 例的构成比例与全 Pilot 不同，不把两者总分直接排名。

| 条件 | Point | Range | 本次来源 |
| --- | --- | --- | --- |
| N | Spectral Residual | Rolling Theil–Sen | 归档 P5 预测 |
| V | semantic-v2 纯视觉 | semantic-v2 纯视觉 | 归档 P7a 预测 |
| U | N/V 精确候选并集 | N/V 精确候选并集 | 同一上游确定性派生 |
| C | U 候选 + 原图，保留/删除 | U 候选 + 原图，保留/删除 | 新调用 qwen3.8-flash |

归档 N/V 文件先检查来源哈希。另在全部 60 例上用新输入专用数值入口重放，复用 P5 阈值，Point/Range 各 60 例与原预测完全相同。没有重新校准 Normal。旧 P5、P6、P7a 及审查并集均保留。

## 3. 推理输入隔离

准备阶段读取 Pilot manifest 的分层元数据，导出 `prepared/inputs/`。其 manifest 只含版本及 case_id、输入 SHA-256、图片 SHA-256；只复制 `input.json`、原无标签 PNG 和 N/V 预测。分层记录及 truth 哈希留在包外的 `selection.json`。不复制 `truth.json`，不重新渲染或叠加标签。

数值入口 `input_only.py` 只读取上述输入及冻结阈值。复核入口 `candidate_review.py` 只读取输入包和复核配置，不调用 `verify_pilot()` 或 evaluator。单独执行评价阶段才打开 truth。这是程序读文件边界和模型请求边界的隔离，并非操作系统权限沙箱；同一用户账户仍有权限访问研究目录。

## 4. 候选与输出契约

Point 按 `(axis, day)` 去重；Range 按 `(axis, start, end)` 去重，不合并交叠区间。按 N/E/U、start、end 排序，赋值 `candidate_0001` 等 ID。相同候选在本地保留 N/V 来源；模型只看到 ID、轴、边界与图，不看到方法名、真值、置信度、案例分层或评测指标。

复核提示明确 Point/Range 活动语义：Point 是孤立日或永久阶跃起点；Range 是持续演化阶段或会恢复的暂时偏移；稳定残留偏移不延长活动期。Point 只能保留原日期，Range 只能保留原端点，不能纠正候选边界。

唯一合法响应为 `{"keep_ids":["candidate_0001"]}`。允许空数组，禁止未知 ID、重复 ID、额外字段、重复 JSON 键、代码围栏和事后修补。模型输出不会作为代码、文件路径或工具命令执行。

## 5. 冻结调用与失败处理

| 参数 | 固定值 |
| --- | --- |
| 请求模型 | qwen3.8-flash |
| thinking / temperature | false / 0 |
| 响应格式 / 输出上限 | JSON Object / 2048 tokens |
| 图片 | 原 1800 × 1200 N/E/U 图；max_pixels=2160000 |
| 分批 | 每批至多 64 候选；每 case×task 至多 18 批 |
| 并发 / 超时 | 4 workers / 120 秒 |
| 尝试 | 每批 1 次；无网络或结构重试 |

Point 三轴最多 1095 个去重日期；Range 可以交叠，1152 是工程预算，不是数学最大区间数。超限不截断，C 记失败。空并集且两上游成功时，C 成功输出空集合，不调用模型。

任一上游失败，U/C 均失败，不回退数值；任何复核批次失败，整例该任务的 C 失败，所有批次原始记录仍保留。失败进入固定 60 例分母，阳性漏报照计；负轴 FAR 只用成功负轴，另外报告执行成功率。旧审查使用视觉失败回退数值，其并集分数不能挪用为本次 U。

预检使用 Pilot 外人工曲线，4 次请求覆盖 Point/Range 单候选及 64 候选载荷。全部结构合法才允许正式运行；预检只验证传输和结构，不是准确率验收，也不证明所有候选数量下模型都稳定。输出文件和实验目录拒绝覆盖；中断后不自动重发已提交请求。

## 6. 评价与复核代价

四条件在相同 60 例上评价。Point 主指标为精确日 micro F1，另报 ±3 日一对一匹配 F1。Range 主指标为有 Range 真值的 case×axis 上 Affiliation F1 的宏平均，另报正轴逐日 IoU 和全轴日 micro F1。FAR 是任务负轴上的报警比例，不是仅 Normal 案例 FAR。Normal 单独报告失败率和报警量。所有定义沿用[多版本评价视图](09-versioned-comparison.md)。

报告同时包含全样本分数，以及 U/C 都成功时的删除效果：Point 分别按精确/±3 日重新匹配，计算删除 FP 和损失 TP；Range 使用日集合差，考虑保留区间的重叠覆盖。复核失败造成的额外漏报不冒称主动删除，在报告中单列失败例数。只删除候选不能超过 U 的候选召回上限，也不能恢复缺失的日期或改好端点。

成本分别记录预检、复核请求与 token/耗时，并列归档视觉候选生成的历史用量。原始数值子集和图片渲染耗时无法准确拆分，保留未知；新数值重放单独保留逐例耗时，首例含初始化。模型没有提供金额时为 null，不把缓存复用称为零端到端成本。复核与历史 V 不同期，服务变化与随机性仍可能影响比较。

## 7. 执行结果

2026-09-27 完成。4 次工程预检全部合法；正式复核 107 次、107 个合法响应，无重试。Point 的 5 个空并集、Range 的 3 个空并集不发请求；Range 的 5 个上游失败同时进入 V/U/C 失败计数。实际候选总数 Point 259、Range 207，单例最大 10/14，本次未触及分批上限；多批正确性由人工 fixture 验证，不声称已在正式样本中验证大候选量模型能力。

| 任务 | 条件 | 主 F1 | ±3 日 F1 / 正轴 IoU | FAR | 成功率 |
| --- | --- | ---: | ---: | ---: | ---: |
| Point | N | 0.5670 | 0.5876 | 0.2314 | 1.0000 |
| Point | V | 0.0708 | 0.4159 | 0.3223 | 1.0000 |
| Point | U | 0.3512 | 0.4167 | 0.4628 | 1.0000 |
| Point | C | 0.2955 | 0.5909 | 0.1736 | 1.0000 |
| Range | N | 0.9132 | 0.3312 | 0.2128 | 1.0000 |
| Range | V | 0.8059 | 0.5513 | 0.2326 | 0.9167 |
| Range | U | 0.8498 | 0.4686 | 0.3721 | 0.9167 |
| Range | C | 0.7597 | 0.4126 | 0.0853 | 0.9167 |

**Point：减少误报，但精确召回损失更大。** U→C 的 FP 从 200 降至 73，同时 TP 从 59 降至 26，精确召回从 0.7662 降至 0.3377，主 F1 下降 0.0557。±3 日重新匹配下删除 142 个 FP、损失 18 个 TP，F1 升至 0.5909；这支持“宽松时间定位下有收益”，不能据此宣布精确日任务成功，也不能将这个补充指标改成事后主指标。

**Range：背景报警下降，活动覆盖也下降。** 在 U/C 同时成功的 55 例中，删除 2119 个 FP 日，损失 419 个 TP 日。全轴日 micro F1 从 0.4227 升至 0.4620，仍低于 N 的 0.4834；主 Affiliation F1 下降 0.0901，正轴 IoU 从 0.4686 降至 0.4126。日级召回从 0.7454 降至 0.5717。多指标结果表明复核偏保守，不能仅凭 FAR 或某一日级 F1 的改善声称整体更好。

Normal 单独看：Point C 在 18 个成功正常轴上仍有 3 个报警轴（0.1667），N 为 1/18；Range C 有 7/15（0.4667），且 6 个 Normal 中 1 例上游失败。N 的 Range Normal 为 0/18。这些 Normal 同属开发材料，小样本比例不能称独立误报保证。主表 FAR 的分母是所有任务负轴，故与此处 Normal-only 比例不同。

成本：正式复核记录 265851 tokens（输入 263947、输出 1904），预检 13660 tokens；本轮新增共 111 次请求、279511 tokens。复核调度墙钟约 33.40 秒，请求耗时之和约 130.37 秒，并发为 4；归档上游视觉 120 次请求的已记录用量为 288803 tokens。包含该上游和本轮预检/复核的已知 token 合计 568314；不含未知的图片渲染/数值原始耗时，费用金额未提供。无追加失败补救请求。

**Gate 结论：本版固定候选复核不进入独立确认。** 两任务的 C 相对 U 主 F1 均下降，未满足预先登记的继续条件。保存其减少过报与牺牲召回的完整证据，保留独立 N/V 基线，不自动运行 300 例确认或 Agent。结果仅适用于这一提示、候选集、模型服务及开发样本；不推断所有视觉复核方法无效。若未来研究新边界修正或不同复核方式，应另立假设、版本和对照，不能覆写本次负结果。

## 8. 可复现入口与产物

2026-09-28 补充：[错误归因与实验链检查](13-p7b-error-analysis.md)已完成，全部冻结报告重算一致；Point 主要误删 Spike 精确日期，Range 活动覆盖损失分布不只在尾段。该检查不修改本文原实验或分数。

```powershell
# 准备 60 例纯输入包，并重放冻结数值方法
uv run python -m gnss_sim.p7b prepare
# Pilot 外工程预检（凭据文件路径由本机指定，不提交凭据）
uv run python -m gnss_sim.p7b preflight --env-file <本机凭据文件>
# 正式复核：只读取准备好的输入包
uv run python -m gnss_sim.p7b run --env-file <本机凭据文件>
# 单独评分：此时才打开 truth
uv run python -m gnss_sim.p7b evaluate
```

已存在的目录会拒绝覆盖，以上不是可重复覆盖的重跑脚本。复现历史计算可读取冻结产物；新模型实验必须使用新目录并明确版本及目的，不能择优替换历史响应。

- `configs/p7b-candidate-review.json`：提示和参数。
- `configs/p7b-registered.json`：正式调用前的源码、配置、输入、选择与预检哈希。
- `configs/p7b-frozen.json`：全部运行产物哈希、指标、成本及 Gate 决策。
- `runs/p7b/prepared/`：分层记录、无真值输入包、数值等价重放记录。
- `runs/p7b/preflight/`：4 次工程预检及原始响应。
- `runs/p7b/candidate-review-v1/`：来源候选、源码快照、逐批原始响应、四条件预测和运行记录。
- `runs/p7b/evaluation/`：汇总、逐案例、分组 JSON 和 Markdown 表。
- `runs/p7b/paper/`：论文 CSV、主指标 PNG/SVG 和完整性审查摘要。`scripts/audit_p7b.py` 实现逐批响应核验、候选重建和八份报告重算，导出也拒绝覆盖。

独立 300 例确认、同期新 V 推理和分层 bootstrap 未启动；本版未通过继续 Gate，停止自动推进组合路线。后续若改变研究假设，需保留此次结果并另立版本。
